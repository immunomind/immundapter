    Infer family trees with RAxML-NG

    Description

    RAxML-NG builds a phylogenetic tree for each sequence family. This tool takes aligned nucleotide sequences from immundata::ImmunData and runs each family independently. It does not define families, align sequences, or reconstruct germlines. Complete those steps before running RAxML-NG.

    RaxmlNgToolConfig stores validated settings for one type of family-level RAxML-NG analysis. It contains no sequences and no trees. Create it with conf_raxml_ng() and pass it to tool_raxml_ng(). The settings cannot be changed after creation; call conf_raxml_ng() again to use different settings.

    Usage

    conf_raxml_ng(
  alignment_col = "clone_sequence_alignment",
  family_col = "clone_id",
  tip_col = immundata::imd_schema("receptor"),
  locus = "IGH",
  analysis = c("search", "fast"),
  model = "GTR+G",
  seed = NULL,
  threads = NULL,
  ancestral = FALSE,
  partition_col = NULL,
  brlen = NULL
)

tool_raxml_ng(config = conf_raxml_ng())

    Arguments

    alignment_col Name of the column containing the aligned nucleotide sequence for each tree tip. This is not IgBLAST’s AIRR sequence_alignment field, which aligns each sequence to a germline rather than to the other sequences in its family.
    family_col Column containing B-cell clone, lineage, or family names or numbers. Each value is analyzed independently.
    tip_col Name of the column containing the sequence name used at each tree tip. The default is the ImmunData receptor ID column.
    locus Receptor locus to use. It must agree with the receptor chains declared by the ImmunData schema.
    analysis Tree-inference mode. “search” performs the standard maximum-likelihood search; “fast” performs the faster search.
    model Non-empty RAxML-NG nucleotide model string. The same model is used for every partition in a partitioned analysis.
    seed Optional positive integer random seed. NULL retains the RAxML-NG default.
    threads Optional positive integer thread count. NULL retains the RAxML-NG automatic default.
    ancestral Whether to run RAxML-NG ancestral-state reconstruction on every successfully inferred family tree.
    partition_col Optional column containing one partition specification per family.
    brlen Optional branch-length linkage mode: “linked”, “scaled”, or “unlinked”. This setting requires partition_col; partitioned runs default to “scaled”.
    config A RaxmlNgToolConfig created by conf_raxml_ng().

    Value

    conf_raxml_ng() returns a read-only RaxmlNgToolConfig. tool_raxml_ng() returns a reusable RaxmlNgTool.

    Input to tool$run()

    tool$run() accepts one immundata::ImmunData dataset. It does not accept a FASTA file directly. The dataset must contain three columns:

    • family_col: Clone, lineage, or family name. A separate tree is built for each value in this column.
    • tip_col: Sequence name shown at the tips, or leaves, of the tree. Each sequence within a family must have a different name.
    • alignment_col: Aligned nucleotide sequence. All sequences in one family must have the same length.

    All three values must be present and non-empty. Repeated rows with the same family, tip, and aligned sequence are used once. A tip cannot have two different sequences in the same family.

    additional_tips optionally supplies backend-only tips that are appended after the observed tips are extracted. It must be a data frame or duckplyr table with family_id, tip_id, and aligned_sequence columns. Its family values must already occur in the extracted input. In a partitioned analysis, an optional partition_spec column must agree with the observed family specification; when omitted, that specification is inherited. Additional tips are never added to or joined into ImmunData.

    outgroups optionally identifies one or more existing tips per family. It must be a data frame or duckplyr table with family_id and tip_id columns. The identified tips may come from ImmunData or additional_tips. RAxML-NG output is rooted by the adapter, which writes a rooted copy of each successful tree while preserving the raw RAxML-NG tree.

    locus selects the receptor chain used for the tree. With paired receptors, only the selected chain is used. The selected locus must agree with the chains stored in the ImmunData dataset.

    If partition_col is set, it must contain one consistent partition specification per family in the form name=start-end, with partitions separated by semicolons. For example, IGH=1-300;IGK=301-540 covers a 540-site alignment. Partitions must be unique, non-overlapping, and cover every alignment site.

    Analysis modes

    The tool supports two RAxML-NG tree-inference commands:

    • “search”: Standard maximum-likelihood tree search.
    • “fast”: Faster tree search.

    Set ancestral = TRUE to run RAxML-NG ancestral-state reconstruction after each successful family tree. This produces a node-labelled tree, reconstructed internal-node sequences, and marginal state probabilities. A failed ancestral stage does not discard the successful family tree. Other modes that use existing trees or produce other types of output, including evaluate, bootstrap, and support, are not part of this tool. The default nucleotide model is GTR+G. Set seed and threads for reproducible execution, or omit them to retain RAxML-NG’s defaults. Partitioned analyses default to scaled branch-length linkage.

    Output from tool$run()

    tool$run() returns a RaxmlNgRun. It records where the results were saved. To read the trees, first run results \<- run$results().

    RaxmlNgResults provides:

    • results$families: One row per family, showing whether the analysis succeeded and where its files were saved. Use dplyr::collect() to read the table into R.
    • results$tree_index: The families that produced a tree and the path to each tree file.
    • results$failed_families: Families that failed, with their exit status and diagnostic message.
    • results$tip_map: The original value from tip_col and the shorter tip label used in the RAxML-NG files.
    • results$outgroups: The original and internal outgroup tip names.
    • results$ancestral_index: Paths to successful ancestral-state files.
    • results$failed_ancestral: Families whose optional ancestral stage failed, with diagnostics.
    • results$read_trees(): One Newick tree per family, returned as a named character vector. When outgroups were supplied, these are rooted copies.
    • results$read_ancestral_trees(): Node-labelled ancestral trees.
    • results$read_ancestral_states(): A duckplyr table of reconstructed internal-node sequences.

    Tree files remain in the run directory. Trees cannot be added as columns to ImmunData. Use $read_trees(), $tree_index, or $tip_map for downstream phylogenetic analysis.

    Each family has its own directory containing the prepared FASTA file, optional partition file, RAxML-NG output, and log files. A failed family does not discard successful results. The returned run has status “partial” when one or more tree or requested ancestral stages fail.

    Examples

    library("immundapter")


sequences <- c(
  "ACGTACGTACGTACGTACGTACGTACGTACGTACGTACGT",
  "ACGTACGTACGTACGTACGTACGTACGTACGTACGTACGA",
  "ACGTACGTACGTACGTACGTACGTACGTACGTACGTTCGT",
  "ACGTACGTACGTACGTACGTACGTACGTACGTTCGTACGT"
)
input_file <- tempfile(fileext = ".tsv")
utils::write.table(data.frame(
  cell_id = paste0("cell-", seq_along(sequences)),
  locus = "IGH", sequence = sequences, clone_id = "family-a",
  clone_sequence_alignment = sequences, duplicate_count = 1L
), input_file, sep = "\t", row.names = FALSE, quote = FALSE)
idata <- immundata::read_repertoires(
  path = input_file,
  schema = immundata::make_receptor_schema(
    features = "sequence", chains = "IGH"
  ),
  barcode_col = "cell_id", locus_col = "locus",
  umi_col = "duplicate_count", repertoire_schema = NULL,
  preprocess = NULL, postprocess = NULL, rename_columns = NULL,
  output_folder = tempfile("raxml-immundata-")
)
config <- conf_raxml_ng(
  alignment_col = "clone_sequence_alignment",
  family_col = "clone_id",
  analysis = "search"
)
tool <- tool_raxml_ng(config)
tool$check()

run <- tool$run(idata, output_dir = tempfile("raxml-ng-run-"))
results <- run$results()
dplyr::collect(results$tree_index)
trees <- results$read_trees()
